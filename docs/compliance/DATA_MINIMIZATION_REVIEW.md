## 1. שדות בשאלה — ניתוח לפי ישות

### 1.1 עובדים (`workers`)

| שדה | נחוצות | סיכון | המלצה |
|-----|--------|-------|--------|
| `full_name` | הכרחי | גבוהה | שמור |
| `national_id` / `passport_number` | הכרחי (ציות חוקי) | גבוהה מאוד | שמור; לשקול הצפנה ברמת שדה |
| `photo_url` | גבוהה — זיהוי; תדריך | גבוהה מאוד (ביומטריה) | שמור; לוודא הסכמה |
| `phone` | בינונית — יצירת קשר | גבוהה | אופציונלי ✓ |
| `notes` | נמוכה — תוכן חופשי | גבוהה (עשוי לכלול רפואי) | לשקול: הנחיות שימוש למנהלים |
| `father_name` | נדרש למינוי מפעיל בלבד | גבוהה | לשקול: הזזה ל-`lifting_machine_appointments` |
| `birth_year` | נדרש למינוי מפעיל | גבוהה | כנ"ל |
| `profession` | נדרש למינוי | בינונית | כנ"ל |
| `address` | נדרש למינוי | גבוהה | כנ"ל |
| `id_number` (legacy) | לתאימות PDF בלבד | גבוהה מאוד | לשקול: NULL-ify בשורות ישנות; הסר משאילתות רגילות |
| `is_foreign_worker` | הכרחי (חישוב סטטוס) | נמוכה | שמור |
| `is_crane_operator` | הכרחי | נמוכה | שמור |
| `worker_type` (legacy) | מיותר (חופף is_foreign_worker) | נמוכה | **להסיר בעתיד** — migration קיים |

**המלצות עדיפות:**
1. שדות `father_name`, `birth_year`, `profession`, `address` — לשקול הזזה ל-`lifting_machine_appointments` כי נדרשים רק שם (יצריך migration — **לא לבצע ללא אישור**)
2. שדה `notes` — הוסף הנחיות UI: "הערות תפעוליות בלבד — אין להזין מידע רפואי"
3. `id_number` legacy — לוודא אחרי migration שהשדה NULL בכל השורות החדשות

### 1.4 הערות ישויות (`entity_notes`)

| שדה | נחוצות | המלצה |
|-----|--------|--------|
| `content` | הכרחי | שמור — אך לשקול character limit |
| `created_by` (free text) | לאחריות | לשקול FK ל-profiles לדיוק audit |
| `status` | שימושי | שמור |

**המלצה:** `created_by` כ-free text אינו מאמת זהות. לצורך audit trail אמיתי, יש לשקול הוספת `created_by_user_id UUID REFERENCES profiles(id)`.

## 2. Storage Bucket — מזעור

| פריט | המלצה |
|------|--------|
| שמות קבצים אנונימיים | ✓ כבר מיושם (timestamp+random) |
| ניקוי קבצים ישנים | ❌ אין מנגנון — להוסיף עתידי |
| קבצי temp / כשלון העלאה | ❌ לא נמחקים אוטומטית |

---

## 3. Cookies ו-Browser Data

| פריט | מצב | המלצה |
|------|-----|--------|
| Session cookie (HttpOnly) | ✓ | שמור |
| Role cookie (non-HttpOnly) | בינוני | ✓ נדרש ל-UI; מינימלי |
| localStorage / IndexedDB | ✓ Cache offline | לוודא שמידע PII לא נשמר ב-cache לא מוצפן |

## 4. API Responses — האם מוחזר יותר מידי?

| נקודת קצה | חשד | המלצה |
|-----------|-----|--------|
| `GET /api/workers` | מחזיר כל השדות | לשקול: projection שמסנן שדות רגישים ל-client |
| `GET /api/workers/[id]` | מחזיר `id_number` legacy | לוודא ש-NULL |
| `GET /api/signed-url` | חשיפת URL זמנית | ✓ TTL מוגבל — OK |

## 5. סיכום פעולות מומלצות (לדיון)

| עדיפות | פעולה | דורש migration? |
|--------|--------|-----------------|
| גבוהה | הנחיות UI לשדה `notes` — "אין להזין מידע רפואי" | לא |
| גבוהה | וודא שדה `id_number` = NULL בכל שורות חדשות | לבדוק |
| בינונית | הוסף `created_by_user_id` ל-`entity_notes` | כן — **לא לבצע ללא אישור** |
| בינונית | אנומליזציה של `worker_type` מ-workers | כן — migration קיים |
| נמוכה | ניקוי אוטומטי של קבצים ישנים | לא |
| נמוכה | API response projection | לא |
