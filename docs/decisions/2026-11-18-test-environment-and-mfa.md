# החלטות פתוחות מוכנות לבחירה — סביבת בדיקות ו-MFA (2026-11-18)

## א. סביבת בדיקות נפרדת (HANDOFF 21)

היום: כל בדיקה עם נתונים רצה מול Production (גם חברת Internal QA יושבת שם). ה-Playwright הקיים אסור להרצה.

| אפשרות | עלות | מה צריך | הערות |
|---|---|---|---|
| **1. Supabase מקומי (Docker) — מומלץ** | $0 | Docker Desktop במחשב; פעם אחת: חיבור ל-DB (מחרוזת חיבור / `supabase login`) כדי לשכפל את הסכמה | מבודד לגמרי, בלי נתונים אמיתיים. Playwright רץ מולו. ה-CI יכול להריץ אותו גם ב-GitHub Actions |
| 2. פרויקט Supabase שני בענן | $0 לפי Supabase, אבל הארגון החינמי מוגבל ל-2 פרויקטים פעילים (יש: SafeDoc, field-quotes) | להשהות את field-quotes, או לשדרג | נוח ל-Preview של Vercel; השהיה משפיעה על field-quotes |
| 3. Supabase Branch | ≈ $0.0134 לשעה (≈ $10 לחודש אם פועל תמיד) | התחייבות כספית | הכי קרוב ל-Production, נמחק ונוצר מחדש |

**מה אני צריך כדי לבצע את 1:** אישור + שתתקין Docker Desktop (או שאתקין אני דרך winget באישורך), ופעם אחת `supabase login` בדפדפן (קוד/אישור שלך). השאר אני עושה: שכפול סכמה (בלי נתונים), נתוני דמה, הרצת Playwright, חיבור ל-CI.

## ב. אימות דו-שלבי (MFA) לאדמינים (HANDOFF 22)

> **הכרעה סופית (2026-11-18):** מומש, ואחר כך הבעלים החליט שהוא **רשות** ולא חובה. אין באנר ואין מועד.

Supabase Auth תומך ב-TOTP (אפליקציית Authenticator) בלי עלות. ההתחברות אצלנו בשרת, ולכן המימוש: אחרי `signInWithPassword` — אם למשתמש יש factor מאומת, השרת מחזיר "נדרש קוד", ורק אחרי `mfa.verify` מונפק ה-cookie `safedoc_session`.

| החלטה | המלצה |
|---|---|
| מי חייב | אדמיני פלטפורמה (`profiles.role = admin`) — חובה. בעלי/מנהלי חברות — רשות בשלב ראשון |
| שחזור כשאובד הטלפון | אדמין פלטפורמה אחר מאפס את ה-factor (Admin API) + רישום ב-`audit_logs`. חייבים לפחות 2 אדמיני פלטפורמה פעילים |
| תקופת מעבר | 14 יום: באנר "הפעל אימות דו-שלבי", אחר כך חסימה עד רישום |
| היקף עבודה | דף רישום (QR), שלב קוד בכניסה, איפוס ע"י אדמין, בדיקות — כיום עבודה אחד-שניים, + בדיקה איתך בטלפון |

**מה אני צריך:** אישור של שלוש השורות הראשונות (או שינוי). אחרי כן אני מממש, בודק בסביבה המבודדת ובחברת QA, ופורס.

## ג. פעולות שרק אתה יכול לבצע (קליק אחד כל אחת)
1. **השבתת מפתחות ה-JWT הישנים** — Supabase Dashboard → Project Settings → API Keys → Legacy API keys → Disable. אומת בלוגים: האפליקציה משתמשת רק במפתחות החדשים, כך שאין השפעה עליה. סוגר את האפשרות שמפתח מאפריל שמור אצל מישהו.
2. **Leaked Password Protection** — דורש תוכנית בתשלום (Pro). החלטה כספית.
