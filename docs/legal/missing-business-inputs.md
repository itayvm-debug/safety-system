# פרטים עסקיים ומשפטיים נדרשים לפני מסחור

**גרסה:** 1.0  
**תאריך:** 2026-09-12  

המסמך הבא מפרט את כל הפרטים שנותרו פתוחים במסמכים המשפטיים והתפעוליים של SafeDoc ודורשים קלט מהנהלה ו/או ייעוץ משפטי. אין להשיק את המוצר לייצור מסחרי עד שפרטים אלה יאושרו ויוכנסו לתוך המסמכים הרלוונטיים.

---

## טבלת פרטים נדרשים

| שדה | היכן נדרש | פעולה נדרשת | אחראי |
|-----|----------|-------------|-------|
| שם הישות המשפטית המפעילה את SafeDoc | מדיניות פרטיות, תנאי שימוש, DPA, מסמך מאגר, הצהרת נגישות | קביעת הישות המשפטית (חברה בע"מ / עוסק מורשה וכו') | יועץ משפטי |
| כתובת הרישום של הישות | מדיניות פרטיות, תנאי שימוש | הנחיית הנהלה | הנהלה |
| כתובת אימייל לפניות פרטיות (GDPR/Privacy) | מדיניות פרטיות, הצהרת נגישות | קביעת כתובת ייעודית ומינוי אחראי לטיפול | הנהלה |
| כתובת אימייל לדיווחי אבטחת מידע | נוהל תקרית אבטחה, נהל ספקים, `security.txt` | קביעת כתובת ייעודית | הנהלה |
| מחזור עסקי שנתי | בדיקת חלות חוק נגישות, בדיקת חובת רישום מאגר | דיווח הנהלה לצורך קבלת חוות דעת משפטית | הנהלה |
| תאריך השקת השירות לראשונה | חלות תקנות הנגישות (לוח זמנים לעמידה) | הגדרת תאריך רשמי לתחילת שירות | הנהלה |
| הגדרת SLA (רמת זמינות מובטחת) | תנאי שימוש — סעיף `[DECISION NEEDED]` | קביעת אחוז זמינות (99%? 99.5%?) ותנאי פיצוי | הנהלה + יועץ משפטי |
| מגבלת אחריות כספית כלפי לקוחות | תנאי שימוש — סעיף `[DECISION NEEDED]` | קביעת תקרת פיצוי (למשל: x חודשי תשלום) | יועץ משפטי |
| תקופות שמירה ספציפיות לפי חוק | מדיניות שמירת מידע (`DATA_RETENTION_REGISTER_HE.md`) | קבלת חוות דעת לגבי: תעודות זהות, מסמכי עבודה, רשומות בטיחות, הערכות עובדים | יועץ משפטי |
| DPA עם Resend (email provider) | רשימת מעבדי משנה, מדיניות פרטיות | חתימה על DPA עם Resend או אישור תנאי DPA הקיימים | הנהלה — בדיקה מול Resend |
| DPA / Terms עם Anthropic (AI provider) | רשימת מעבדי משנה, מדיניות פרטיות, העברות בינלאומיות | בדיקת תנאי עיבוד נתונים של Anthropic API; האם מספיקים? | הנהלה — בדיקה מול Anthropic |
| אישור DPA חתום עם Supabase | רשימת מעבדי משנה | אישור שה-DPA של Supabase חתום ותקף | הנהלה — תיעוד |
| אישור DPA חתום עם Vercel | רשימת מעבדי משנה | אישור שה-DPA של Vercel חתום ותקף | הנהלה — תיעוד |
| ביצוע Penetration Test | נוהל אבטחת מידע, ביקורת ציות | תכנון ותיאום עם גורם מקצועי מאושר | הנהלה + אבטחת מידע |
| סמכות שיפוט מוסכמת ודין חל | תנאי שימוש — סעיף 11 | ברירת מחדל: ישראל. אם לקוחות בינלאומיים צפויים — לדון | יועץ משפטי |
| תהליך ערעור עובד על הערכה | ממשל הערכות עובדים, בקרות פרטיות הערכות | קביעת תהליך פורמלי (ראה `docs/legal/employee-review-governance.md`) | הנהלה |
| הכרזה על פטור/עמידה בנגישות | הצהרת נגישות | קבלת חוות דעת משפטית + ביצוע בדיקה מקצועית | יועץ משפטי + גורם נגישות |

## סדר עדיפויות מומלץ

### לפני כל לקוח ראשון (חובה)
1. שם ישות משפטית + כתובת
2. אימייל לפניות פרטיות ואבטחה
3. DPA חתום עם כל ספקי המשנה (Supabase, Vercel, Resend, Anthropic)
4. עדכון מדיניות פרטיות לגרסה 1.2 (כולל Anthropic)
5. גרסה סופית של תנאי שימוש ו-DPA לחתימת לקוחות

### לפני הגעה ל-10+ לקוחות (מומלץ בדחיפות)
6. Penetration Test
7. הגדרת SLA ומגבלת אחריות
8. תקופות שמירה מאושרות משפטית
9. בדיקת חלות חוק נגישות + בדיקה מקצועית

### לפני קמפיין שיווקי / הגדלת לקוחות משמעותית
10. `security.txt`
11. עדכון הצהרת נגישות
12. בדיקת חובת רישום מאגר מידע
