# תוכנית המשכיות עסקית — SafeDoc

**גרסה:** 0.1  
**תאריך:** 2026-09-12  

> **מסמך המלצות — לא הוגדרו עדיין יעדי RTO/RPO מאושרים.**  
> יעדי זמן השחזור (RTO — Recovery Time Objective) ויעדי נקודת השחזור (RPO — Recovery Point Objective) דורשים קביעה מפורשת על-ידי ההנהלה. עד לקביעתם, מסמך זה מהווה מסגרת המלצות בלבד.

---

## 1. עקרון מנחה

**ספיגת תקלה של SafeDoc לא תמנע מחברות לקוח למלא את חובותיהן החוקיות.** חברות בנייה מחויבות בדיווחי בטיחות, תיעוד, ורישומים על-פי חוק הבטיחות בעבודה. בזמן השבתה, הלקוח יכול לעבוד עם רשומות ידניות ולייבא לאחר חזרת המערכת לפעילות.

---

## 2. תרחישי תקלה

| שירות | תרחיש כשל | השפעה על SafeDoc | פתרון חלופי עד לשיקום |
|-------|-----------|----------------|----------------------|
| **Vercel** | השבתה מלאה / deploy כושל | האתר אינו נגיש בכלל; אף משתמש אינו יכול להיכנס | אין; מומלץ: דף status page פשוט (ראה סעיף 4) |
| **Supabase — DB** | השבתת PostgreSQL | כל פעולות CRUD לא עובדות; לוגין נכשל; uploads נכשלים | אין; נתונים קיימים בגיבוי; RTO תלוי ב-Supabase SLA (Pro plan: 99.9%) |
| **Supabase — Storage** | השבתת Object Storage | קבצים (תמונות, מסמכים) לא נגישים; PDFs לא ניתנים להפקה | ייתכן שיש קבצים שמורים מקומית אצל הלקוח; ניתן להציג מידע ללא קבצים |
| **Resend** | תקלה בשירות האימייל | דוחות שבועיים ותזכורות לא נשלחות | ידני: מנהל SafeDoc יכול לייצא דוח דרך הממשק ולשלוח ידנית; אין אובדן נתונים |
| **Anthropic API** | תקלה ב-AI | OCR לא עובד (`/api/ai/extract-worker-identity`) | הזנת נתוני עובד ידנית על-ידי המשתמש; פונקציה זו אינה קריטית לפעולה |
| **Vercel Edge Network** | תקלה CDN | תת-קבוצה של משתמשים גיאוגרפיים מושפעת | Vercel מנתב לאזור חלופי; השפעה זמנית בלבד |
| **SESSION_SECRET rotation (חירום)** | SESSION_SECRET דלף / נגנב | כל המשתמשים מנותקים מיד לאחר החלפת ה-Secret | **עיצוב מכוון** — מחייב את כל המשתמשים להתחבר מחדש; תקין |

---

## 3. גיבויים

| שכבה | שיטת גיבוי | תדירות | אחריות |
|------|-----------|--------|-------|
| **Supabase DB** | Point-in-time recovery (PITR) — Pro plan | רציף (WAL streaming) | Supabase (על-פי SLA) |
| **Supabase Storage** | גיבוי פנימי של Supabase | תדירות לפי SLA | Supabase |
| **Vercel** | Deploy snapshots; rollback זמין | לפי כל deploy | Vercel |
| **ZIP export ידני** | ייצוא מלא דרך ממשק מנהל | ידני — לפי שיקול הנהלה | SafeDoc + לקוח |

> **RPO:** עם PITR של Supabase Pro, RPO תיאורטי הוא דקות בודדות לנתוני DB. לנתוני Storage — `[MANAGEMENT/LEGAL REVIEW REQUIRED]`.

> לפרטים מלאים על גיבויים ושיחזור ראה `docs/BACKUP_AND_RECOVERY_RUNBOOK_HE.md`.

## 4. תקשורת עם לקוחות בעת תקלה

**`[MANAGEMENT INPUT REQUIRED]`**

יש להחליט על ערוץ העדכון בעת תקלה:

| אפשרות | יתרון | חיסרון |
|--------|-------|--------|
| דף status page פשוט (למשל: Statuspage.io או עמוד סטטי ב-Vercel) | מידע זמין גם כשהאפליקציה כבושה | נדרש hosting נפרד |
| עדכון אימייל ידני | פשוט לתפעול | לא סקיילבל בעת תקלות רבות |
| WhatsApp לאיש קשר ראשי בכל לקוח | ישיר; מוכר בתעשייה הישראלית | ידני |

**המלצה:** הקמת status page בסיסי (אפילו פשוט כגון Cloudflare Pages / GitHub Pages) שמציג מצב שירות. דף זה חייב להיות מתארח באופן עצמאי ממערכת SafeDoc עצמה.

## 5. בדיקה תקופתית

**מומלץ:** בדיקת תרחיש המשכיות עסקית **פעם בשנה**, הכוללת:

1. סימולציית שיחזור מגיבוי DB — אימות שה-PITR עובד.
2. בדיקת rollback של deploy — וידוא שניתן לחזור לגרסה קודמת ב-Vercel.
3. עדכון תוכנית זו בהתאם לשינויים בארכיטקטורה.
