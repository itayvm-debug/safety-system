# בקרות פרטיות — מודול הערכות עובדים

**גרסה:** 1.0  
**תאריך:** 2026-09-12  
**סיווג:** מסמך פנימי — בקרות תפעוליות  

> מסמך זה מתאר את בקרות הפרטיות הקיימות והמומלצות עבור מודול הערכות העובדים של SafeDoc. אין במסמך זה כדי להחליף ייעוץ משפטי.

---

## 1. מטרת המסמך

מטרת מסמך זה להגדיר את כללי הגישה, העיבוד, השמירה והחשיפה של נתוני הערכות עובדים ב-SafeDoc, ולהנחות את הצוות המפתח ואת הלקוחות העסקיים (חברות הבנייה) בשימוש אחראי במודול.

---

## 2. סיווג המידע

הערכות ביצוע שבועיות הן **מידע אישי רגיש** מהסיבות הבאות:

- הן מכילות ציונים מספריים (בין 1 ל-10) ב-6 תחומים לגבי עובד ספציפי.
- הן עשויות לכלול תגובת מנהל בכתב חופשי — שיכולה להכיל מידע אישי מכל סוג.
- הציונים והתגובות עשויים **להשפיע על החלטות תעסוקה** כגון: העלאת שכר, קידום, הצבה, ואף פיטורים.
- מידע זה אינו גלוי לעובד המוערך דרך מערכת SafeDoc, ולכן קיים אי-סימטריה מידעית שמחייבת בקרה.

**קטגוריות נתונים בהערכה:**

| שדה | תיאור | האם מידע אישי? |
|-----|--------|---------------|
| `worker_id` | מזהה עובד | כן |
| `week_start` | שבוע ההערכה | לא |
| `score_attendance` | ציון נוכחות (1–10) | כן |
| `score_safety` | ציון בטיחות (1–10) | כן |
| `score_quality` | ציון איכות עבודה (1–10) | כן |
| `score_teamwork` | ציון עבודת צוות (1–10) | כן |
| `score_communication` | ציון תקשורת (1–10) | כן |
| `score_responsibility` | ציון אחריות (1–10) | כן |
| `manager_comment` | תגובת מנהל חופשית | כן — פוטנציאל לתוכן רגיש |
| `evaluator_manager_id` | מזהה המנהל המעריך | כן |
| `company_id` | מזהה החברה | כן (בעקיפין) |

---

## 3. מטריצת גישה למידע

| תפקיד | מה הוא/היא יכול לראות | מה אסור לו/לה לראות |
|-------|----------------------|---------------------|
| `owner` / `admin` (בחברה) | כל הערכות העובדים בחברה שלהם — ציונים, תגובות מנהל, שם מעריך | הערכות של חברות אחרות |
| `member` (מנהל עם הרשאה) | רק הערכות של עובדים שהוקצו אליו (`worker_review_assignments`) | הערכות שהוקצו למנהלים אחרים; הערכות לעובדים שאינם תחת אחריותו |
| `viewer` | אין גישה להערכות כלל | כל הערכות |
| מנהל פלטפורמה (platform admin) | מטה-נתונים לצרכי ביקורת (company_id, timestamps) | תוכן ההערכות עצמו |

> גישה לכל ההערכות אינה מוענקת אוטומטית לכל מנהל — היא מוגבלת להקצאות המוגדרות ב-`worker_review_assignments`.

---

## 4. בקרות טכניות קיימות

הבקרות הבאות מיושמות בצד השרת ואינן ניתנות לעקיפה על-ידי ה-client:

1. **`evaluator_manager_id` נקבע בצד השרת** — בעת שמירת הערכה, המערכת קובעת את מזהה המנהל המעריך על-פי ה-session, ואינה מקבלת ערך זה מה-client.
2. **אילוץ ייחודיות שבועית** — אילוץ `UNIQUE (worker_id, week_start)` בטבלה מונע הגשת יותר מהערכה אחת לעובד לשבוע נתון.
3. **סינון לפי `company_id`** — כל שאילתא לנתוני הערכות מסוננת לפי `company_id` של המשתמש המחובר. לא ניתן לגשת להערכות מחברה אחרת.
4. **הקצאות מנהל** — גישת מנהל (`member`) מוגבלת לעובדים המופיעים ב-`worker_review_assignments` עם ה-`manager_id` שלו.

## 5. ייצוא וחשיפה

| ערוץ | כולל נתוני הערכות? | הערות |
|------|------------------|-------|
| Admin ZIP export | **כן** — `worker_weekly_reviews` כלול | מכוון לצורכי ניידות נתונים; יש לציין ב-DPA עם לקוחות |
| Reviews report API (`/api/reviews/report`) | **כן** — נתון מלא (ציונים + תגובות) | נגיש ל-owner/admin בלבד, מסונן לפי company_id |
| דוח בטיחות שבועי (אימייל) | **לא** | מכיל סטטוס מסמכים ותפקודי בטיחות בלבד — ללא ציונים |
| תבניות WhatsApp | **לא** | ללא נתוני הערכות |
| PDF עובד (client-side) | **לא** | מסמכי רישוי ותעודות בלבד |
| תזכורת מנהל (אימייל, יום חמישי) | **לא** | מכיל מספר הערכות ממתינות בלבד — ללא שמות או ציונים |

## 6. הנחיות לכתיבת תגובות מנהל

מנהלים המשתמשים בשדה תגובת המנהל נדרשים לפעול לפי הכללים הבאים:

- **כתוב תצפיות מקצועיות בלבד** — התייחסות לאיכות העבודה, עמידה בנהלים, בטיחות, ותקשורת מקצועית.
- **אל תכלול מידע אישי שאינו נוגע לעבודה** — מצב בריאותי, מצב משפחתי, דעות פוליטיות, שיוך עדתי, או כל מידע שאינו רלוונטי לביצוע התפקיד.
- **אל תשתמש בלשון פוגעת, מבזה, או מפלה** — גם אם מדובר בביקורת כנה, יש לנסחה בלשון מקצועית ומכבדת.
- **הערכה שמתיימרת לתאר את אישיות העובד** אינה הערכת עבודה — הישאר בתחום ביצועי התפקיד.
